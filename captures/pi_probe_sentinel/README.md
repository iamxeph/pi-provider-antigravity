# Probe capture — `skip_thought_signature_validator` on the Antigravity backend

Not an `agy` CLI fingerprint (see `../README.md`): the official CLI never replays a
tool call authored by another provider, so this uncovered case can only be probed with
this extension's own request builder. This is the evidence behind the sentinel injection
in `src/builder.ts` (`SKIP_THOUGHT_SIGNATURE_VALIDATOR`).

Captured 2026-09-10 through `mitmdump -p 18080`, model `gemini-3.8-flash-low`, history =
one user turn + one **unsigned** `functionCall` (`bash`, no `thoughtSignature`) + its
`functionResponse` — i.e. a cross-provider tool turn (the session that surfaced this:
an `opencode-go/muse-spark-1.3-contributor` tool call between two
`antigravity/gemini-3.8-flash` turns) replayed as the pending step of the current turn.

| Fixture | Request body | Response |
|---|---|---|
| `stream_probeA_unsigned.req.json` | as built — unsigned `functionCall` | `stream_probeA_unsigned.resp.json` — **400** INVALID_ARGUMENT "Function call is missing a thought_signature in functionCall parts. … `default_api:bash` , position 2" |
| `stream_probeB_sentinel.req.json` | byte-identical body + `thoughtSignature: "skip_thought_signature_validator"` on that single part | `stream_probeB_sentinel.resp.sse` — **200**, model answers `ok` |
| `stream_probeC_claude_unsigned.req.json` | same shape on a Claude runtime model (`claude-sonnet-4-6`), unsigned | `stream_probeC_claude_unsigned.resp.sse` — **200**: the Claude wire requires no signature here |
| `stream_probeD_claude_sentinel.req.json` | same body + the sentinel | `stream_probeD_claude_sentinel.resp.sse` — **200**: tolerated, but pointless |

B differs from A only in that one field, so the sentinel is the single variable: the
backend accepts it in place of the signature it would otherwise demand (Google documents
it for `functionCall` parts "not generated by the API … when transferring history from a
model that does not include thought signatures"). C/D show the divergence is
Gemini-specific: the Claude wire neither needs nor benefits from it, so the builder leaves
Claude/GPT requests alone (`docs/adr/0007-sentinel-divergence-for-foreign-calls.md`).

## Re-running

1. Start the runbook proxy (`../README.md` §1), record the PID, keep port 18080.
2. Build the A body with `buildAntigravityRequestBody`: messages `[user, assistant
   (provider `opencode-go`, one `toolCall` without `thoughtSignature`), toolResult]`,
   `tools` = a `bash` declaration; POST to `v1internal:streamGenerateContent?alt=sse`
   with the stored Antigravity token from `~/.config/pi/auth.json`.
3. POST `structuredClone(A)` with `thoughtSignature: "skip_thought_signature_validator"`
   set on the unsigned `functionCall` part.
4. Node's `fetch` needs `NODE_USE_ENV_PROXY=1` and
   `NODE_EXTRA_CA_CERTS=~/.mitmproxy/mitmproxy-ca-cert.pem` to traverse the proxy.
5. Expected today: A → 400 with the message above, B → 200; C and D (Claude runtime
   model) → 200 both. If B ever stops returning 200 the sentinel has been retired and
   `src/builder.ts` must change with it.
6. For a Claude runtime model, `maxOutputTokens` must exceed the plan's
   `thinkingConfig.thinkingBudget` — anything smaller is rejected before the history is
   ever validated (`max_tokens must be greater than thinking.budget_tokens`).
7. `npm run sanitize:captures captures/pi_probe_sentinel && npm run lint:captures` before
   committing, and delete the raw flows — they hold a `Bearer` token.
8. Teardown: `setsid nohup mitmdump … &` records the wrapper's PID in `$!`, not the
   proxy's — read the real one from `ps -eo pid,cmd | grep '[m]itmdump'` and kill that,
   then confirm `ss -ltn | grep 18080` is empty.
9. Re-captured fixtures stay machine-checked: `tests/wire-parity.test.mjs` (ADR-0007 gate)
   asserts each pair differs only in `thoughtSignature` after the per-call `requestId` and
   `content-length` are removed, that the baseline carries none, and that exactly one part
   carries the sentinel — so a re-capture must preserve that single-variable property.
